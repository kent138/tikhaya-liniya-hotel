# Тихая линия

Авторский портфолио-проект премиального бутик-отеля. Русский интерфейс, рубли, четыре категории номеров и полный демонстрационный путь от выбора дат до номера брони. Гостиница, отзывы, контакты и расстояния — иллюстративные.

## Быстрый старт

Требуется Node.js 22 или новее.

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

Vite обслуживает интерфейс. Vercel Functions обслуживают `/api/*`; локальная Vite-разработка использует деморежим. Для проверки серверных функций используйте Vercel CLI `vercel dev` с настроенным окружением.

## Что работает в опубликованном деморежиме

- Главная с большой фотографией, формой поиска, рассказом об отеле, услугами, галереей, отзывами, местами рядом, FAQ и картой OpenStreetMap.
- Отдельные страницы Standard, Comfort, Deluxe и Suite с галереями, характеристиками и удобствами.
- Проверка вместимости, дат и доступности каждого физического номера; пересекающиеся брони исключаются из поиска. Дата выезда не занимает следующую ночь.
- Завтрак, трансфер, парковка, ранний заезд и поздний выезд. Завтрак рассчитывается на гостя за день, парковка — за ночь.
- Контактные данные, согласие, номер брони, сохранение деталей в текстовый файл и отмена бронирования.
- `/admin`: обзор, календарь по месяцам, поиск гостей, подтверждение и отмена, 12 физических номеров, 4 статуса, тарифы, блокировки и история.
- Новые тарифы применяются к новым бронированиям; суммы существующих броней остаются прежними.
- Состояние хранится в localStorage конкретного браузера, ключ `tikhaya-liniya-demo-v1`. Другие посетители имеют независимые данные. Telegram и email в деморежиме не отправляются, оплата не принимается. Для тестов используйте вымышленные контакты.

## Подготовленная серверная интеграция

Серверный режим включается только при наличии всех трёх обязательных переменных: `DATABASE_URL`, `ADMIN_PASSWORD_HASH` и `SESSION_SECRET` длиной не менее 32 символов. Без них сайт остаётся демонстрационным. Не задавайте только часть конфигурации для рабочего приёма гостей.

1. Создайте PostgreSQL-базу с TLS, например через провайдера, подключённого к Vercel.
2. Задайте `DATABASE_URL` в защищённых переменных окружения и выполните `npm run db:migrate` с этой переменной. Миграция идемпотентна; существующие данные и цены сохраняются.
3. Подготовьте hash пароля локально с функцией `passwordHash` из `server/core.js` (scrypt, случайная соль). Храните результат в `ADMIN_PASSWORD_HASH`, а случайную секретную строку — в `SESSION_SECRET`. Пароль и секреты не должны попадать в Git, журналы, аргументы команд или клиентский код.
4. Для Telegram задайте `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в Vercel. Бот должен иметь доступ к указанному чату. После создания брони сервер отправляет администратору её данные; результат доставки фиксируется в истории. Ошибка Telegram не отменяет сохранённую бронь.
5. Выполните новый deployment и проверьте реальный сценарий с тестовыми контактами, включая одновременные запросы, авторизацию и получение Telegram-уведомления.

API рассчитывает цены самостоятельно, проверяет входные данные и использует параметризованные SQL-запросы. Транзакция блокирует физические номера выбранной категории перед повторной проверкой доступности. Сессия администратора подписана HMAC, действует 8 часов и хранится в HttpOnly/Secure/SameSite cookie. Предусмотрены ограничение попыток входа и частоты запросов, проверка Origin и индивидуальный токен отмены. Публичный API не возвращает список гостей.

Серверный режим подготовлен в исходниках, но **не подключён к базе и Telegram и не проверен с настоящим PostgreSQL** в этой поставке. Перед коммерческим запуском также требуются реальные контакты, условия отмены/оплаты, юридические документы, политика хранения данных, резервное копирование базы и очистка старых строк `rate_limits`. Email-рассылка и платёжный шлюз не реализованы.

## Архитектура

```text
src/
  components/   форма поиска, карточка номера, доступная галерея
  pages/        главная, номер, бронирование, админ-панель
  lib/          данные, расчёт цены и демонстрационное хранилище
  App.jsx       навигация и общий контекст
server/         валидация, авторизация, SQL и миграция
api/            Vercel Functions
scripts/        предварительный HTML-рендеринг
tests/          цена, валидация, доступность, пароль и сессии
public/images/  локальные оптимизированные фотографии
```

React 19, Vite 7, Lucide, PostgreSQL через postgres.js. Страницы номеров, бронирование и панель загружаются отдельными чанками. Главная и страницы номеров предварительно рендерятся в HTML, имеют отдельные title, description, canonical, Open Graph и JSON-LD; генерируется sitemap. Админ-панель и бронирование закрыты от индексации. При смене домена обновите `base` в `scripts/prerender.mjs`.

Адаптивная сетка, нативные поля, aria-метки, управление галереей с клавиатуры, фокус внутри модального диалога, skip-link, контрастные ошибки и поддержка `prefers-reduced-motion`. Картинки хранятся локально, второстепенные загружаются лениво. Skeleton отображается при загрузке страниц и поиске.

## Проверки этой поставки

- Сборка production и предварительный рендер пяти публичных страниц.
- Автоматические проверки расчёта суммы, валидации, пересечений/отмены/блокировки, хеширования пароля и срока сессии.
- Ручной браузерный сценарий: поиск → Standard → завтрак и парковка → контакты → номер брони; сумма 13 600 ₽ за 2 ночи для 2 гостей.
- Отображение в календаре и списке гостей, подтверждение/отмена, изменение и восстановление тарифа.
- Главная и Deluxe на ширине 390 px, загрузка фотографий, отсутствие горизонтального переполнения.
